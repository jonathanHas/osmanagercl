## How the track runs

- Planner writes `docs/planImp/plan.md` (Status READY); the Opus implementer writes `docs/planImp/implemented.md`; the Planner reviews (reads the report to the end, reruns the suite, reads the diffs), sets ACCEPTED and archives both to `docs/planImp/archive/<date>-shop-mode-cycle-NN/`. Only the Planner sets ACCEPTED. The Planner never edits application code and never commits, pushes or deploys; the owner commits.
- Side plans (`plan-<slug>.md` / `implemented-<slug>.md`) when `plan.md` is busy; post-acceptance findings go in `docs/planImp/findings/` and are archived with the cycle that fixes them; unimplemented plans go to `docs/planImp/parked/`.
- Take the test baseline at planning time with `php artisan test` (other tracks add tests). Current: **15 failed / 921 passed**; the 15 are pre-existing and unrelated (UdeaScrapingService ×7, CashReconciliation ×3, FruitVegLabelPrinting ×2, Product ×2, TestScraperController ×1).
- Every response ends with `mpg123 /home/jon/Music/notification.mp3` (CLAUDE.md).
- Design copy lives in `docs/design/shop-mode/` (Claude Design project `9402165e-9955-461d-8ff4-3e934897b600`). The design block of `resources/css/shop.css` must stay byte-identical to `docs/design/shop-mode/shop.css`; check with `head -c $(stat -c %s docs/design/shop-mode/shop.css) resources/css/shop.css | cmp - docs/design/shop-mode/shop.css`. App rules only under `/* === APP ADDITIONS START === */`. Views under `resources/views/shop/**` use only `x-shop.*` components and `shop-*` classes (`tests/Feature/Shop/ShopViewContractTest.php`).
- Production reads only: `ssh -n -o BatchMode=yes jon@lilThink2 'cd /var/www/html/osmanager && php artisan tinker --execute=…'`. Production is HTTPS; the dev host (`osmanager.local`) is plain HTTP, so the live camera cannot run on dev — camera cycles are verified with spies in the browser and by the owner on production.
- Dev browser checks: `resize_window` does not change the viewport; use a same-origin iframe sized 390×844 for phone measurements. The idle lock (5 min) fires on a trusted device during long checks. Dev data the implementer writes is put back afterwards and listed under "Dev state" in each report.
